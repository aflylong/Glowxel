# 设备页响应式单页规范

## 1. 目标

`website` 里的设备控制相关页面统一走“一套路由 + 一套 mobile 页面 + 页面内响应式 PC 适配”方案。

这份规范主要解决 3 个问题：

1. 不再同时维护 `pc` / `mobile` 两套页面。
2. PC 适配只写在页面自己内部，不再靠 `body` 级全局覆盖补样式。
3. 后续新页面先把骨架、滚动和断点规则定好，再继续堆业务内容。

## 3. 核心原则

### mobile 端

1. 保持原来的页面结构和交互密度。
2. 保持原来的自然上下滚动。
3. 不要为了 PC 适配，把 mobile 强行限制成单屏。
4. 不要新增只给 mobile 生效的兼容壳。

### PC 端

1. 页面使用固定宽度容器，不要全屏铺满。
2. PC 适配是附加能力，不能破坏 mobile 原样式。
3. 预览区和配置区可以做左右分栏，但必须由页面自己控制。
4. 顶栏、返回按钮、标题加粗等视觉规则要和当前 mobile 设计语言保持一致。

## 4. 禁止事项

后续开发禁止继续做下面这些事情：

1. 新增一套独立的 PC 页面。
2. 再用 `deviceDual(...)` 做 PC / mobile 双页面切换。
3. 再往 `body.xxx` 或公共壳里堆页面级全局覆盖。
4. 不分析页面结构，直接用全局补丁去“压”某一个页面。
5. 为了修 PC 把 mobile 的滚动、高度、底栏行为一起改坏。

## 5. 页面改造约定

### 页面骨架

设备页默认保留下面这些原始结构：

1. `status-bar`
2. `navbar`
3. `canvas-section` 或页面主预览区
4. `content`
5. `bottom-tabs`（如果页面本来就有）

### 样式策略

1. mobile 基础样式继续写在页面本身的 `scoped style` 里。
2. PC 响应式写页面自己的 `@media (min-width: 769px)`。
3. 如果页面还会被旧全局补丁命中，就在当前页面里用更明确的选择器接管回来。
4. 只处理当前页面需要的布局，不抽新的全局桌面补丁。

### PC 端常见落地方式

1. 页面外层固定宽度：`width: min(1180px, calc(100vw - 48px))`
2. 页面整体固定高度：`height: calc(100vh - 32px)`
3. 顶栏转页面内静态区域，返回按钮单独定位
4. 左侧预览区固定，右侧配置区内部滚动
5. 底部 tab 在桌面端收进页面内部，不再继续依赖底部吸附逻辑

## 7. 路由规范

设备页单页化后，路由直接指向唯一的 mobile 页面：

```js
{
  path: "/your-page",
  name: "YourPage",
  component: () => import("@/views/mobile/YourPage.vue"),
  meta: { shell: "app", deviceSinglePage: true },
}
```

说明：

1. `shell: "app"` 保持设备页的应用壳环境。
2. `deviceSinglePage: true` 表示这个页面已经迁到单页响应式方案。
3. 不再给同一路由挂第二个 PC 实现。

## 8. 后续开发顺序

后续继续改设备页时，按这个顺序：

1. 先确认该页面能不能直接以 `mobile` 页面为唯一来源继续演进。
2. 先保住 mobile 的滚动、底栏和主交互，不要先动这些。
3. 再在页面内部补 PC 的固定宽度、顶栏、分栏和内容滚动。
4. 最后再收 UI 细节，比如卡片密度、按钮尺寸、标题层级和空白节奏。
